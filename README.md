# 동작 거울 (pe-motion-trainer)

특수교육(중도·중복장애 포함) 기초 체육·협응 훈련용 웹앱 MVP.
웹캠 자세 인식(MediaPipe Pose)으로 학생 체형에 맞춘 **반투명 목표 실루엣**을 거울 화면에 겹쳐 보여 주고,
닌텐도 스위치 **조이콘(WebHID)** 의 좌/우 독립 HD 진동과 IMU 스윙 감지로 촉각 피드백을 준다.

- 카메라 영상은 브라우저 안에서만 분석한다. 저장·전송하지 않는다. (외부에서 받는 것은 인식 모델 파일뿐)
- 조이콘이 없어도 카메라만으로 모든 기능을 쓸 수 있다. 스윙은 **스페이스바**로 대신한다.

---

## 1. 실행

필요: Node.js 20 이상, **Chrome 또는 Edge** (WebHID는 이 두 브라우저만 지원)

```powershell
cd C:\Users\박정인\dev\pe-motion-trainer
npm install        # 처음 한 번
npm run dev        # → http://localhost:5173 을 Chrome으로 연다
```

- 카메라 없이 화면만 점검: `http://localhost:5173/?sim` (가상 학생이 차렷 → 목표 동작 → 복귀를 반복)
- 배포용 빌드: `npm run build` → `dist/` 폴더 전체를 Netlify(끌어다 놓기)나 GitHub Pages에 올린다.
  HTTPS 주소여야 카메라·WebHID가 동작한다(GitHub Pages·Netlify는 기본 HTTPS).

### 학교망에서 모델 파일이 막힐 때
인식 모델은 기본적으로 `storage.googleapis.com` 에서 받는다. 막혀 있으면 집 등 다른 망에서 한 번:
```powershell
npm run fetch-models
```
→ `public/models/` 에 저장되고, 이후 앱이 로컬 파일을 먼저 쓴다(빌드하면 `dist/`에도 포함).

## 2. 조이콘 연결 (Windows + Chrome)

1. 조이콘을 스위치 본체·그립에서 분리한다.
2. 조이콘 레일(본체에 끼우는 면)의 작은 동그란 **SYNC 버튼**을 LED가 좌우로 흐를 때까지 약 3초 누른다.
3. Windows **설정 → Bluetooth 및 장치 → 장치 추가 → Bluetooth** → `Joy-Con (L)` 선택. R도 같은 방법으로.
4. 앱 첫 화면(또는 오른쪽 위 🎮) → **조이콘 연결·진단** → 왼쪽 카드의 **연결하기** → Chrome 창에서 `Joy-Con (L)` → 연결.
   오른쪽도 같은 방법. 조이콘 LED가 깜박임을 멈추고 하나로 고정되면 성공.
5. 진단 창에서 **진동 약하게 / 세게 / 타격** 버튼으로 좌우가 따로 울리는지, 조이콘을 휘둘러 **💥 스윙!** 칸이 노랗게 켜지는지 확인.

- 한 번 허용한 조이콘은 다음부터 같은 브라우저에서 **자동 재연결**된다.
- 안 될 때: Steam·BetterJoy 등 조이콘을 잡는 프로그램을 끈다 / Windows 블루투스에서 장치 제거 후 다시 페어링 / 스위치 본체가 근처에서 켜져 있으면 본체로 붙을 수 있으니 끈다.

## 3. 사용 흐름

1. **▶ 시작** → 카메라 허용
2. **가만히! (2초)**: 차렷 자세(서거나 앉은 채)로 어깨너비·윗팔·아랫팔·상체(전신 모드는 다리까지) 길이를 측정
3. 목표 실루엣이 학생 몸에 맞춰 겹쳐 나온다. 부위가 맞으면 그 부위가 **형광 초록**, 같은 쪽 조이콘이 **톡** 울리고 유지하는 동안 약하게 박동
4. 모든 판정 부위를 **유지 시간** 동안 지키면 축하 진동(왼-오 핑퐁 후 양쪽 크게) + 효과음 + 파티클 + ⭐
5. 라켓·티볼: ① 대기 자세 유지 → **⚡ 준비 완료 진동** → 5초 안에 ② 조이콘(또는 스페이스바) 스윙 → **💥 타격음 + 묵직한 진동**

### 교사 설정 (오른쪽 위 ⚙️)
| 항목 | 내용 |
|---|---|
| 동작 | 양손 만세 / 앞으로 나란히 / 몸 수그리기 / 라켓·티볼 대기+스윙 |
| 자세 모드 | 전신 / 상체(좌식·휠체어) — 상체 모드는 다리를 판정·표시에서 뺀다. 바꾸면 재측정 |
| 허용 오차 | 15°(정밀) ~ 45°(관대). 각 뼈의 목표 방향과 실제 방향의 3D 각도 차 |
| 유지 시간 | 0.5 ~ 3.0초. 0.25초 미만의 순간 이탈은 봐준다(떨림 배려) |
| 진동 세기 | 0 ~ 100% (감각 예민 학생은 낮게) |
| 스윙 기준 | 1(살짝) ~ 5(세게). 라켓 동작에서만 보임 |
| 보기 | 겹치기(기본) / 나란히 |
| 인식 | 빠른(lite) / 정확한(full) 모델, 카메라 선택 |
| 판정 상세 | 부위별 일치 여부, 뼈별 각도 오차(°), 인식 fps |

설정은 브라우저에 자동 저장된다.

### 가이드 렌더링 수식
목표 동작은 픽셀이 아니라 **뼈마다 두 각도**로 정의한다 (학생 몸 기준, 좌우 대칭).
- `raise`: 정면 평면에서 아래(0°)→옆(90°)→머리 위(180°), 음수는 몸 안쪽
- `fwd`: 정면 평면에서 앞(카메라)으로 기운 각 (90° = 정면으로 곧게)

```
방향 d = ( sin(raise)·cos(fwd),  −cos(raise)·cos(fwd),  sin(fwd) )    // (바깥, 위, 앞)
화면 2D = ( d.바깥 × 좌우부호,  −d.위 )                                // 정사영 → 앞으로 뻗으면 자동으로 짧아짐
자식관절 = 부모관절 + 화면2D × (캘리브레이션 비율 × k)                     // k = 현재 어깨너비(px, 평활)
굵기 = 기본굵기 × clamp(1 + 0.5 × 누적깊이, 0.75, 1.9)                   // 앞으로 나올수록 굵게 = 원근감
```
- **캘리브레이션 비율** = √(2D 길이² + (world 깊이차 × px/m)²) ÷ 어깨너비, 2초간 중앙값
- **판정**: 실제 뼈 방향 = 화면 평면 성분은 2D 랜드마크, 앞뒤 기울기 φ는 world z에서 →
  `(2D단위벡터 × cos φ, sin φ)`. 목표 방향과의 3D 사잇각 ≤ 허용 오차이면 일치.
- 팔은 학생 실제 어깨에, 몸 수그리기처럼 몸통이 판정 대상이면 엉덩이에서 세운 목표 어깨에 붙인다.
- 영상·캔버스 모두 CSS `scaleX(-1)` 로 거울 반전 → 학생의 왼팔이 화면 왼쪽, 왼손 조이콘이 울린다.

### 조이콘 WebHID 패킷
| 방향 | 리포트 | 내용 (리포트 ID 제외 바이트) |
|---|---|---|
| PC→JC | `0x01` 진동+서브커맨드 | `[0]`카운터(0~15 순환) `[1-4]`L진동 `[5-8]`R진동 `[9]`서브커맨드 `[10~]`인자 |
| PC→JC | `0x10` 진동만 | `[0]`카운터 `[1-8]`진동 |
| JC→PC | `0x21` 서브커맨드 응답 | `[12]`ACK `[13]`서브커맨드 ID |
| JC→PC | `0x30` 표준 전체(60Hz) | `[1]`배터리 `[12-47]` IMU 3샘플 × (가속 xyz, 자이로 xyz) int16 LE |

초기화: `0x48 01`(진동 켜기) → `0x40 01`(IMU 켜기) → `0x03 30`(전체 입력 모드) → `0x30`(LED)

HD 진동 4바이트 (고주파 HF·저주파 LF 대역 각각 주파수·세기):
```
freqCode = round(log2(Hz/10) × 32)
HF = (freqCode − 0x60) × 4      LF = freqCode − 0x40
ampCode  = round(log2(a×8.7)×32)  (a>0.23) | round(log2(a×17)×16) (a>0.12) | round(log2(a×100)×4)+1
byte0 = HF & 0xFF
byte1 = (HF>>8) + ampCode×2
byte2 = LF + (LFamp>>8)
byte3 = (ampCode>>1) + 0x40
무진동 = 00 01 40 40 (320Hz/160Hz, 세기 0)   세기 상한 1.0 (하드웨어 보호)
```
- 모든 출력 리포트는 한 줄로 직렬화하고, 진동은 최신 값만 보낸다(블루투스 적체 방지).
- 50ms보다 긴 진동 구간은 50ms마다 재전송.
- 스윙: 자이로 크기 ≥ 기준(250~1400°/s) 또는 |가속도|−1g ≥ 기준(0.7~3.0g), 0.7초 재감지 금지.

## 5. 알려진 한계 (실기기 검증 필요)

- **웹캠 한 대(정면)로 앞뒤 깊이를 추정**한다. 앞으로 나란히·몸 수그리기·대기 자세는 화면 평면 동작보다 판정이 덜 안정적일 수 있다 → 허용 오차를 30° 이상으로 시작하고 **판정 상세**의 각도를 보며 조정한다.
- 학생이 카메라를 정면으로 보고 있어야 한다(몸을 많이 돌리면 앞뒤 판정이 틀어진다).
- 조이콘 진동·IMU 코드는 공개된 리버스엔지니어링 문서 기준으로 작성했고, 이 저장소에서는 패킷 바이트 단위 테스트만 했다. 실제 조이콘 동작은 진단 창으로 확인한다.
- 스윙 기준값(°/s, g)은 일반적인 값으로 잡았다. 학생에 맞춰 1~5단계로 조정한다.
